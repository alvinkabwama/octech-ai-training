# Week 2: Chatbot (memory, streaming, API) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Week 2 lesson, starter and stubbed tests: a session-based chatbot with bounded
memory, streaming and a FastAPI front, plus `llm.chat_stream()` in the shared helper.

**Architecture:** `exercises/common/llm.py` gains a streaming twin of `chat()`, and
`FakeClient` learns to stream so tests stay offline. The week's `starter/chatbot.py` holds
the logic (in-memory sessions, trimming, reply, streamed reply); `starter/api.py` is a thin
FastAPI layer over it, the same pattern the mini-EDRMS uses.

**Tech Stack:** Python 3.10+, openai SDK 3.x (`stream=True`), FastAPI + Pydantic v2,
`fastapi.testclient`, pytest, ruff.

**Spec:** `docs/superpowers/specs/2026-11-11-octech-ai-training-design.md` (sections 3, 5.2,
10.2, 10.3) and the trainer's week 2 brief of 2026-11-20 (recorded in
`trainer-notes/train-log.md`).

## Review Focus

1. A message that is only spaces must be rejected (422), not sent to the model; pinned by
   `test_bad_messages_are_rejected` and `test_api_rejects_bad_body`.
2. A failed model call must not leave a half-saved turn: the user can simply retry; pinned
   by `test_failed_model_call_returns_fallback_and_saves_nothing`.
3. The stream endpoint must answer 404/422 *before* streaming starts (`reply_stream`
   validates eagerly); pinned by `test_reply_stream_checks_before_streaming` and the API 404 test.
4. Trimming must never start the history on an `assistant` message, and must not mutate
   the caller's list; pinned by `test_trim_history_keeps_system_and_last_turns`.
5. A 429 mid-stream must not retry (it would duplicate text the user has already seen);
   pinned by `test_chat_stream_does_not_retry_after_first_piece`.

### Task 2: week 2 tests, starter and lesson

**Files:**
- Create: `exercises/week-2-chatbot/{LESSON.md, starter/chatbot.py, starter/api.py,
  starter/live.py, tests/test_chatbot.py, tests/test_api.py}`

**Interfaces (starter/chatbot.py):** `SYSTEM_PROMPT: str` ("Octech Help"),
`MAX_MESSAGE_CHARS = 2000`, `MAX_TURNS = 6`, `FALLBACK_REPLY: str`,
`class UnknownSessionError(KeyError)`, `SESSIONS: dict[str, list[dict[str, str]]]`,
`new_session() -> str`, `end_session(session_id) -> None`,
`trim_history(messages, max_turns=MAX_TURNS) -> list[dict[str, str]]`,
`reply(session_id, text) -> str`, `reply_stream(session_id, text) -> Iterator[str]`.
A *turn* starts at a `user` message. `trim_history` keeps the system messages plus everything from
the `max_turns`-th-last user message on, and returns a new list. The stored history is kept trimmed.
On `LLMError`, `reply`/`reply_stream` return or yield `FALLBACK_REPLY` and save nothing.
`reply_stream` raises `ValueError`/`UnknownSessionError` before returning its iterator.
**starter/api.py:** `app`. `POST /chat` `{session_id?: str, message: str}` → `{session_id, reply}`.
`POST /chat/stream` → `text/plain` stream plus an `X-Session-Id` header.
`DELETE /chat/{session_id}` → 204. Unknown session → 404; bad body or message → 422; `extra="forbid"`.
The tests load `api.py` with the starter folder on `sys.path` (it does `import chatbot`).

- [ ] **Step 1:** write `tests/test_chatbot.py` (13) and `tests/test_api.py` (5), using `fake_llm`
  only. They cover:

  - a long conversation capped at 12 messages

  - an unknown session; empty, space-only and 2,001-character messages
  - the fallback with nothing saved
  - stream pieces joined and saved; eager validation; no user text in logs
  - API 200, 404, 422 (empty, spaces, too long, extra field, missing message), the stream endpoint
